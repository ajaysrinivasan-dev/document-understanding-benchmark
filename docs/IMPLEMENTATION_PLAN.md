# Implementation Plan

## Architecture
- Python package with separate ingestion, preprocessing, OCR/layout, VLM, extraction, evaluation, benchmarking, API, and UI layers.
- A shared `DocumentResult` schema is the contract between pipelines and consumers.
- Optional heavy integrations (Tesseract/PyMuPDF/Transformers) are loaded behind adapters; core schemas, normalization, evaluation, and tests remain CPU-only.

## Components
- Ingestion converts PDF/image inputs into page objects with stable metadata.
- OCR/layout produces words, bounding boxes, page references, candidate fields, and practical table candidates.
- VLM adapter targets configurable Qwen vision-language models and validates strict JSON output.
- Extraction and normalization provide deterministic, extensible field/table handling.
- FastAPI exposes extraction and health/info endpoints; Streamlit provides a thin demo client.

## Dataset Strategy
- Annotations use JSON documents containing `document_id`, `document_type`, `fields`, and `tables`.
- `data/samples/` contains only clearly labeled development fixtures, never benchmark claims.
- Real annotated documents belong under ignored `data/raw/` and `data/annotations/`; dataset manifests record provenance and versions.

## Evaluation Methodology
- Normalize predictions and ground truth deterministically before comparison.
- Report exact and normalized field metrics, precision/recall/F1, per-field/type/document breakdowns, and table structure/column/row/cell scores.
- Record missing, incorrect, hallucinated, formatting, layout, and document-quality failures without collapsing them into a single score.

## Baseline
- OCR words retain text, confidence, page, and bounding box data.
- Layout grouping uses page geometry and configurable heuristics to create reading-order text and table candidates.
- The baseline is explicitly represented as OCR/layout output rather than treated as equivalent to VLM inference.

## VLM Pipeline
- Configurable model name and runtime settings from environment/CLI.
- Images/pages are passed to a strict extraction prompt requesting schema-constrained JSON.
- JSON is parsed and validated; malformed or unavailable model output returns warnings/errors safely.

## Comparison Methodology
- Both processors run against the same document inputs and annotation set.
- Metrics are generated by the independent evaluator; latency/resource samples are measured per pipeline and environment.
- No result is published until generated from real annotations and an actual run.

## Testing Strategy
- Pytest covers schemas, normalization, table parsing, adapter conversion, malformed VLM output, metrics, API validation, and health checks.
- Fake processors/models avoid GPU or model downloads.
- Ruff and formatting checks run locally and in CI; optional type checking is configured where practical.

## Deployment Strategy
- FastAPI runs in a non-root container with size/type validation, safe temporary files, request IDs, structured logs, and no document-content logging.
- VLM model weights remain external to the image unless explicitly provisioned by the deployment environment.
- Docker Compose supports local API use; Streamlit remains a separate optional UI process.

## Expected Deliverables
- Working repository structure and shared schemas.
- OCR/layout and configurable VLM pipeline adapters.
- Deterministic evaluation, failure analysis, benchmark scripts, and report generation.
- FastAPI service, Streamlit UI, tests, Docker/Compose, CI, configuration examples, architecture/evaluation/security documentation, and experiment records.
- Explicit documentation of unavailable real data, optional dependencies, model/runtime requirements, and any validation not executable in the current environment.
